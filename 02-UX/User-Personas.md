# User Personas

## Overview

This document defines the primary user personas for Shipyard from a UX perspective. These personas guide user experience decisions, navigation, workflows, interface hierarchy, and feature prioritization throughout the design process.

While the PRD defines product requirements for each persona, this document focuses on how each user interacts with the product and what they need to accomplish efficiently.

---

# Primary Persona

## Software Engineer

### Description

Software Engineers are the primary users of Shipyard. They spend most of their time managing assigned work, updating issue status, collaborating with teammates, and completing development tasks within active projects and cycles.

### Primary Goals

- Quickly understand assigned work
- Track issue progress
- Collaborate through comments
- Update issue status with minimal effort
- Stay informed about relevant activity

### Needs

- Fast navigation
- Minimal clicks
- Clear issue organization
- Responsive interface
- Low cognitive load

---

# Secondary Persona

## Engineering Lead

### Description

Engineering Leads coordinate developers, plan development cycles, assign work, monitor project health, and ensure the team delivers on schedule. They require visibility across the entire workspace while minimizing manual coordination.

### Primary Goals

- Plan development cycles
- Assign and prioritize work
- Monitor project and team progress
- Balance team workload
- Identify and remove blockers

### Needs

- High-level dashboards
- Project and cycle visibility
- Efficient issue management
- Team workload awareness
- Clear progress tracking

---

# Secondary Persona

## Startup Founder / Product Manager

### Description

Startup Founders and Product Managers define what the team should build by planning the product roadmap, creating projects, prioritizing work, and monitoring overall delivery. Their focus is strategic planning rather than day-to-day execution.

### Primary Goals

- Plan the product roadmap
- Prioritize development work
- Organize projects
- Monitor delivery progress
- Maintain visibility across the workspace

### Needs

- Simple project planning
- Clear progress dashboards
- Easy prioritization
- Minimal management overhead
- Fast access to project insights

---

# Shared UX Principles

Regardless of role, every user experience should prioritize:

- Speed over complexity
- Clarity over customization
- Consistency across workflows
- Keyboard-first interactions where appropriate
- Minimal context switching
- Predictable navigation
- Immediate feedback for user actions

---

# Design Priority

Although Shipyard supports multiple personas, every UX decision should prioritize the Software Engineer experience first, as they are the most frequent users of the platform.

Engineering Leads and Startup Founders / Product Managers should be able to accomplish their workflows using the same interface through appropriate permissions, navigation, and workspace views, rather than requiring separate experiences.
